# Project Specific Guidelines: STRICT 2-MINUTE BUILD/REBUILD MODE

Follow these rules strictly for all subsequent turns in this project:

## ⚡ BUILD/REBUILD EXECUTION RULES
1. **STRICT 2-MINUTE TIMELIMIT**: "Build" or "Rebuild" operations must be fully optimized and completed under a hard 2-minute deadline. Do not delay with excessive planning or long explanations.
2. **Build Guidelines**: Understand requirements instantly and generate a complete, working, single-file `index.html` application.
3. **Rebuild Guidelines**: Analyze existing work carefully and apply targeted modifications only. Do not rewrite parts of the code unnecessarily.
4. **Single-File Structure**: Keep HTML, CSS, and JavaScript structured together inside a single, robust `index.html` file whenever possible.
5. **No Fake Elements / Placeholders**: Every requested button, navigation link, state toggle, and interaction must be 100% functional. Never use dry placeholders, dead buttons, or mockup screens.
6. **Keep It Lightweight**: Avoid adding heavy external libraries, bloated code, or unnecessary server dependencies unless explicitly requested.
7. **No Unnecessary Rewrites**: Never rewrite existing, fully functional code without a clear and logical reason.
8. **Targeted Bug Fixing**: If a build error occurs, do not scrap the project. Pinpoint the root cause and execute a targeted, surgical fix.
9. **Instant Self-Testing**: Perform quick code quality/linter self-checks immediately after any edits to prevent obvious runtime errors.
10. **Priority Matrix**: `WORKING` ➔ `COMPLETE` ➔ `UI QUALITY` ➔ `EXTRA POLISH`

## 🔒 SAFETY & RELIABILITY RULES
1. **Analyze First, Edit Second**: Always review the current codebase before making edits. Do not break or regress any existing feature.
2. **Impact Analysis**: Prior to making changes, explain clearly:
   - Which files will be modified.
   - What risks are involved and how they will be mitigated.
3. **No Over-Engineering**: Edit only what is requested in the prompt. Do not add unrequested "bonus" features or visual tabs.
4. **Permanent Fixes Only**: Fix bugs thoroughly so that the user does not experience any glitches, crashes, or regressions.
5. **Pre-delivery Guarantee**: Always test the build and provide a clear assurance/guarantee that all modifications have been successfully validated and are fully operational.
